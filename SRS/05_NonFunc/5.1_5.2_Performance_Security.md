# 5 Non-Functional Requirements

## 5.1 Performance Requirements

### NFR-PERF-001: Page Load Time

**Title**: Dashboard and main views load within acceptable time

**Description**: The system shall load the dashboard page within 2 seconds for 95% of requests under normal load conditions.

**Acceptance Criteria**:
- Dashboard loads in < 2 seconds on average
- First Contentful Paint < 1.5 seconds
- Time to Interactive < 2 seconds

---

### NFR-PERF-002: API Response Time

**Title**: API endpoints respond quickly

**Description**: The system shall return API responses for all endpoints within 500ms for 95% of requests.

**Acceptance Criteria**:
- 95% of API calls return < 500ms
- Expense creation < 200ms
- Expense listing (batch) < 300ms

---

### NFR-PERF-003: Concurrent Users

**Title**: System supports expected user concurrency

**Description**: The system shall support up to 10 concurrent authenticated users.

**Acceptance Criteria**:
- No errors with 10 concurrent login attempts
- Response time degradation < 25% at max load

---

### NFR-PERF-004: Data Volume

**Title**: System handles reasonable data volume

**Description**: Each user shall be able to store at least 1000 expense records without performance degradation.

**Acceptance Criteria**:
- 1000 expenses listed with pagination
- Page load time < 2.5 seconds with 1000 records

---

## 5.2 Security Requirements

### NFR-SEC-001: Password Storage

**Title**: Passwords securely hashed with bcrypt

**Description**: User passwords shall be hashed using bcrypt algorithm with cost factor of at least 12 before storage in the database.

**Acceptance Criteria**:
- Password hashed with bcrypt
- Cost factor >= 12
- Salt included in hash
- Plain-text password not stored

---

### NFR-SEC-002: Authentication Security

**Title**: JWT tokens used for session management

**Description**: The system shall use JWT (JSON Web Tokens) for stateless session management with automatic expiration after 24 hours of inactivity.

**Acceptance Criteria**:
- Valid JWT on each protected request
- Expired tokens rejected with 401 status
- Token signature verified

---

### NFR-SEC-003: Input Sanitization

**Title**: All user inputs sanitized before processing

**Description**: The system shall sanitize all user inputs to prevent injection attacks.

**Acceptance Criteria**:
- SQL injection prevented via parameterized queries
- XSS prevented via output encoding
- HTML input escaped in responses

---

### NFR-SEC-004: HTTPS Enforcement

**Title**: All communication encrypted in transit

**Description**: The system shall enforce HTTPS for all client-server communication.

**Acceptance Criteria**:
- HTTP requests redirected to HTTPS
- Valid SSL/TLS certificate used

---

### NFR-SEC-005: Authorization Checks

**Title**: Users can only access their own data

**Description**: The system shall enforce that users can only read, modify, or delete their own expense records.

**Acceptance Criteria**:
- User cannot modify another user's expense
- Attempt returns 403 Forbidden
- User ID verified in all data operations
