## 3.2 Expense Management Requirements

### FR-EXP-001: Add Expense

**Title**: User can record a new expense

**Description**: The system shall allow an authenticated user to add a new expense with amount, date, category, and optional description. The expense shall be stored with a reference to the authenticated user.

**Priority**: Mandatory

**Acceptance Criteria**:
- User can add expense on the expense form
- Amount field accepts numeric values (2 decimal places)
- Date field accepts valid date format (YYYY-MM-DD)
- Category must be selected from existing categories
- Description is optional and accepts alphanumeric text
- Expense is saved with correct user association
- Success confirmation displayed

---

### FR-EXP-002: View Expenses

**Title**: User can view their expenses

**Description**: The system shall display a list of expenses belonging to the authenticated user, sorted by date in descending order by default. Each expense shall display amount, date, category, and description.

**Priority**: Mandatory

**Acceptance Criteria**:
- List shows only user's expenses
- Expenses sorted by date (newest first)
- Pagination implemented for > 50 expenses
- Each row displays amount, date, category, description
- Clickable row navigates to expense detail

---

### FR-EXP-003: Edit Expense

**Title**: User can modify their expense details

**Description**: The system shall allow an authenticated user to edit amount, date, category, and description of their own expense. Changes shall be saved to the database.

**Priority**: Mandatory

**Acceptance Criteria**:
- Only owner can edit their expense
- All editable fields available for modification
- Validation rules apply to edited values
- Previous values must have been different from new values
- Success confirmation displayed

---

### FR-EXP-004: Delete Expense

**Title**: User can remove their expense

**Description**: The system shall allow an authenticated user to delete their own expense. Deletion shall be permanent and cannot be undone.

**Priority**: Mandatory

**Acceptance Criteria**:
- Only owner can delete their expense
- Confirmation dialog appears before deletion
- Deleted expense no longer appears in list
- Database record is permanently removed
- Success confirmation displayed

---

### FR-EXP-005: Validate Expense Data

**Title**: Expense input data is validated before saving

**Description**: The system shall validate that amount is a positive number with maximum 2 decimal places, date is not in the future, category exists, and description (if provided) is within character limit.

**Priority**: Mandatory

**Acceptance Criteria**:
- Zero or negative amounts are rejected
- Future dates are rejected
- Non-existent categories are rejected
- Description > 500 characters is rejected
- Clear error messages for each validation failure

---

## 3.3 Category Requirements

### FR-CAT-001: View Categories

**Title**: User can view available expense categories

**Description**: The system shall display all available categories that a user can assign to expenses. Categories shall be displayed in alphabetical order.

**Priority**: Mandatory

**Acceptance Criteria**:
- Category list displayed on expense form
- Categories sorted alphabetically
- Default categories present: Food, Transport, Entertainment, Utilities, Shopping, Other
- User can see category colors/icons

---

### FR-CAT-002: Assign Category to Expense

**Title**: User can assign a category when creating or editing expense

**Description**: The system shall allow selection of an existing category when adding or editing an expense. The selected category shall be stored as a foreign key reference.

**Priority**: Mandatory

**Acceptance Criteria**:
- Dropdown with categories available
- Category selection saved with expense
- Invalid category ID is rejected
- User cannot delete categories with existing expenses
