## 3.5 Search and Filter Requirements

### FR-SF-001: Search Expenses

**Title**: User can search expenses by description or category name

**Description**: The system shall provide a search function that filters expenses based on partial matches in the description field or category name. Search shall be case-insensitive.

**Priority**: Mandatory

**Acceptance Criteria**:
- Search input accepts alphanumeric text
- Results update as user types (debounced)
- Matches partial strings (e.g., "groc" matches "Grocery")
- Search is case-insensitive
- Clear results when search cleared
- Shows "No results found" message when no matches

---

### FR-SF-002: Filter by Category

**Title**: User can filter expenses by category

**Description**: The system shall allow a user to filter the expense list to show only expenses belonging to a selected category.

**Priority**: Mandatory

**Acceptance Criteria**:
- Dropdown or list of categories available for filtering
- "All Categories" option shows all expenses
- Filtered results update immediately
- Category filter independent of other filters
- Active filter indicator shown

---

### FR-SF-003: Filter by Date Range

**Title**: User can filter expenses by date range

**Description**: The system shall allow a user to specify a start date and end date to filter expenses within that date range.

**Priority**: Mandatory

**Acceptance Criteria**:
- Date pickers for start and end dates
- Invalid date range (end before start) is rejected
- Date format displayed as YYYY-MM-DD
- Results update after date selection
- Date filter combined with other filters
