# 1.3 Intended Audience

The intended audiences for this SRS document are:

## Primary Audiences

| Audience | Role | Purpose |
|----------|------|---------|
| Team Leader | Backend Lead | System architecture, database design, API specification, integration coordination |
| Member 1 | Auth Frontend | Login/Signup page design, frontend authentication flow, input validation |
| Member 2 | Expenses Frontend | Expense form design, list view, edit interface |
| Member 3 | Expenses Backend | Expense API endpoints, CRUD operations, data validation |
| Member 4 | Dashboard | Statistics calculation, summary display, chart integration |
| Member 5 | Search/Filter | Search functionality, filter UI components, API query parameters |
| Member 6 | Categories | Category management UI, assignment to expenses |
| Member 7 | Testing/QA | Test case development, requirements validation, documentation review |

## Secondary Audiences

| Audience | Role | Purpose |
|----------|------|---------|
| Course Instructor | Project Evaluator | Assessment of project completeness, requirement clarity, implementation quality |
| Quality Assurance | Tester | Verification that all requirements are properly tested |
| Future Developers | Maintainers | Understanding requirements for system maintenance and enhancement |

## Document Convention

- Requirement IDs follow the pattern: FR-[MODULE]-[number] for functional, NFR-[CATEGORY]-[number] for non-functional
- Use case IDs follow pattern: UC-[module]-[number]
- All requirements are numbered and traceable
